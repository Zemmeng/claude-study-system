### ① 🆕 `shared/工具/对齐.py` —— 零 token 看别的对话在干什么

**原来只有两条路，都不够用**：
· `活动会话.tsv` —— 靠会话**自觉登记**，不是实况，忘登记就没有
· MCP 的 `list_sessions` + `list_events` —— 准，但每次几千 token，**只在开场跑一次**

🔑 **发现**：CCD 的 transcript 就在 `~/.claude/projects/<slug>/<sessionId>.jsonl`，**可以直接读**。
文件 **mtime = 最后活动时间**（比 MCP 的 `lastActivityAt` 还直接），`tail` 几百行就拿到最近对话。
当前会话自己的 id 在环境变量 **`CLAUDE_CODE_SESSION_ID`** 里（09-03 实测确认）。

→ `对齐.py` 输出每个活会话「他最后说了什么 / 我最后说了什么」，**零 token、毫秒级**。
🔒 **写进 `总控.md` 的对齐表第 1 位：每次他发言都跑，不只是开场。**
🔒 **判据：`对齐.py` 是实况，`活动会话.tsv` 是登记。不一致时信 `对齐.py`，然后去修登记表。**

⚠️ 过滤掉 `isSidechain`（子 agent 的对话）和 hook 注入的系统提示，只留他和主线说的话。

### ② 多 agent 审查：**每个 agent 必须先落盘再返回**

**根因**：Workflow 脚本本身**没有文件系统访问**（工具说明写死），结果只能等全部跑完由主会话落盘。
🔴 **09-03 12:38 实测**：8 个维度的 fable 审查跑 9 分钟被喊停，`journal.jsonl` 只保住 **1 个**，
其余 7 个无法结构化恢复；而 `resumeFromRunId` **只在同一会话有效**。

🔑 **解法：子 agent 自己有 Bash 和 Write。** 在 prompt 里写死两条 ——
① 开工前看 `shared/审计/<维度>.md` 在不在，**在就读出来当结果返回，不重跑**
② 做完先写进那个文件，**再**返回结构化结果

**效果**：跑完一个落一个（中途停不丢）· **天然断点续跑，不依赖 same-session 缓存** · 主会话能 `ls` 看进度。
🔒 **配套：usage 紧时一批只跑 2–3 个维度**，别一次丢 8 个进去。
做法和 prompt 模板 → `shared/工具手册.md` 末节 + `shared/审计/README.md`。
