## 触发词「编译 / 排版」—— xelatex 跑两遍

**xelatex 一般已在 PATH；`command -v xelatex` 找不到再查用户目录里的安装（例：`~/texlive/<年份>/bin/<平台>`），把那个目录加进 PATH 再跑。**

```
xelatex -interaction=nonstopmode -halt-on-error x.tex     # 跑两遍
# 🔒 发出去之前（2026-09-05 他定，主 CLAUDE.md 讲解形态第 8 条）：
#   grep -c "^!" x.log            # 必须 0 —— nonstopmode 会静默跳过错误，PDF 照常生成但图没画出来
#   grep -c "Overfull \\hbox" x.log   # 必须 0
#   pdftoppm -png -r 58 x.pdf <scratchpad>/chk && 每一页 Read 一遍看图
```

- ⚠️ **`command -v xelatex` 查不到，别据此说「没装」** —— TeX Live 常装在用户目录而不在 PATH 里，先查一遍再下结论
- 宏包齐全：`ctex` `xeCJK` `amsmath` `amssymb` `geometry` `fancyhdr` `xcolor` `tcolorbox` `enumitem` `pifont`
- CJK 字体用 `\setCJKmainfont{PingFang SC}`（macOS 自带；**Latin Modern 里没有中文**。Songti SC 与 Helvetica 混排别扭，字体四件套见 `next.md` 的排版节）
- ⚠️ **`✓ ✗ ⚠` 这类字符 Latin Modern 渲染不出来**，用 `pifont` 的 `\ding{51}` / `\ding{55}`
- **代码块里的长命令会冲出页面** —— `md2pdf.py` 已加 `fvextra` + `breaklines=true`
  （自动折行，续行前打 `↪`）。**新写 `.tex` 时记得也加**，`fancyvrb` 的 `Verbatim` 默认不折行
- **`⌘` `⇧` 这类快捷键符号 PingFang / Menlo / Helvetica 都没有字形**，渲染时会被吃掉
  → **写成 `Cmd+Shift+4` 这种纯文字**
- **`md2pdf.py` 不认表格单元格里的 `<br>`**，会原样打出来 → 用「；」或分成两行

**排版/编译命令我自己跑，不要丢给他**（2026-08-19 他定）：

| ❌ 不做 | ✅ 做 |
|---|---|

| 「你跑一下这个命令重新编译」 | 改完 `.tex` **当场自己编译**，顺手清掉 `.aux/.log/.out` |
| 让他自己转格式、自己装包 | 我做掉；**真需要他授权的（下载、装软件）才问一句** |

**判据：这条命令是「基建」还是「他要学的东西」？**
· **基建**（编译、转格式、归档、跑检查脚本、装宏包）→ **我跑，不解说**
· **他要学的**（`javac`/`java` 跑自己的 Java 代码、实验作业里必须他手动敲的
　`traceroute`/`ping`/`iperf`）→ **给他命令，他自己跑**
　⚠️ 作业 spec 明说**必须本人手动执行并截图**的实验步骤，不属于「基建」，这条不适用

## 触发词「`.docx`」= 一律用 LaTeX 重排一版（2026-08-19 他定）

| 路子 | 结果 |
|---|---|
| ❌ `textutil` → HTML → Chrome headless | 能转，内容不丢，**但丑** |

**做法**：
1. `python3` + `zipfile` 读 `word/document.xml`，正则剥标签取全文
   （`unzip -l` 先看有没有 `word/media/`，有图要另外抽出来）

3. `xelatex` 跑两遍 → **`.tex` 和 `.pdf` 都留在项目里**，`.docx` 原件也别删
4. 要归 Zotero 的话，**在 `~/Downloads` 放一份**（他从那儿拖进 Zotero）

⚠️ **说清楚一句**：这是**重新排版**，不是像素级复刻 —— 版式和 Word 里打开的不一样。
当索引/骨架用没问题，**但如果那份文件的原始版式本身有意义**（表格式的表单、要按原样填的官方文件），
**原件为准**，重排版只当参考。

## 🔒🔒 跑多 agent 审查时，**每个 agent 必须先落盘再返回**

> 他 2026-09-03 21:4x 提的：「**有没有把这个唤起多个子 agent 的时候把每个子 agent 的内容进度保存一下呢
> 因为感觉一次性 我这个五个小时的 usage 好像不是很够用**」

### 为什么会丢

**Workflow 脚本本身没有文件系统访问**（工具说明写死的：*No filesystem or Node.js API access*），
所以结果只能等**全部跑完**由主会话落盘。中途停掉 → 已经跑完的 agent 的成果**一起丢**。

🔴 **09-03 12:38 实测过一次**：8 个维度的审查跑了 9 分钟被喊停，
`journal.jsonl` 里只保住 **1 个**跑完的，其余 7 个的中间过程无法结构化恢复。
而 `resumeFromRunId` **只在同一会话有效**，开新对话就用不上缓存。

### 🔑 解法：子 agent 自己有 Bash 和 Write

**在每个 agent 的 prompt 里写死这两条：**

```
【落盘 —— 必须做，在返回结果之前】
1. 开工前先看 `shared/审计/<维度key>.md` 在不在：
   **在就说明这个维度已经做过了，直接把它读出来当结果返回，不要重跑。**
2. 做完后，先把完整发现写进 `shared/审计/<维度key>.md`（用 Write），**再**返回结构化结果。
```

**效果**：
- ✅ **跑完一个落一个** —— 中途停掉也不丢
- ✅ **天然断点续跑** —— 下次重跑时已完成的维度秒过，不烧 token，**且不依赖 same-session 缓存**
- ✅ 主会话可以随时 `ls shared/审计/` 看进度

### 配套：一次别跑太多

🔒 **usage 有限时，把维度拆成每批 2–3 个**，跑完一批看一眼再决定下一批。
❌ 别一次丢 8 个维度进去 —— 那是 09-03 那次丢掉 7 份成果的直接原因。

### 收尾

审查做完、结论落进正式档案（`规则档案.md` / 各流程文件）之后，
把 `shared/审计/*.md` 归并成一份留档（例：`shared/审计-<主题>-<日期>.md`），清空 `shared/审计/`。
