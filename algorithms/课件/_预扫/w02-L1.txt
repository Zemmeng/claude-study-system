The Problem: Searching a Sorted Array
            Input an array A[0..n − 1] sorted in increasing order, and a key x
          Output an index j with A[j] = x , or −1 if x is not in A
    Linear search ignores the order and may scan everything.
    The order should let us rule out many positions with one comparison.

===== w02-L1 viewer p.5 =====
Binary Search: Pseudocode
    function BinSearch(A, x, n)
        lo <- 0
        hi <- n - 1
        while lo <= hi
            mid <- floor((lo + hi) / 2)
            if A[mid] = x
                return mid
            else if A[mid] < x
                lo <- mid + 1
            else
                hi <- mid - 1
        return -1

===== w02-L1 viewer p.7 =====
Why Must A Be Sorted?
    The loop maintains an invariant:
    Invariant
    If x occurs in A, then it occurs in A[lo..hi].
       • A[mid] < x : sortedness means everything at or left of mid is < x , so discarding it
         is safe
       • On an unsorted array the same discard can throw away x

===== w02-L1 viewer p.8 =====
Analysis
    Basic operation: the comparison A[mid] against x .
       • Best case: x is at the first midpoint, so 1 comparison
       • Worst case: the range halves every round; let C (n) be the comparisons:
          C (n) = C (⌊n/2⌋) + 1,   C (1) = 1   =⇒    C (n) = ⌊log2 n⌋ + 1 ∈ Θ(log n)
