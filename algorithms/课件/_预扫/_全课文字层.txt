       • Worst case: x is absent, so n comparisons
       • Best case: x is in the first position, so 1 comparison

Big-O: The Definition
    O(g(n)) is the set of functions that grow no faster than g.
    Definition
    t(n) ∈ O(g(n)) iff there exist constants c > 0 and n0 such that t(n) ≤ c · g(n) for all
    n > n0 .
    Example. 3n + 10 ∈ O(n).
    For n > 10 we have 3n + 10 < 3n + n = 4n, so choose c = 4 and n0 = 10.

===== w01-L1 viewer p.7 =====
Big-Omega and Big-Theta
       • t(n) ∈ Ω(g(n)): t(n) ≥ c · g(n) for all n > n0 – a lower bound
       • t(n) ∈ Θ(g(n)): both O(g) and Ω(g) – the exact order of growth
    Caution. Writing 3n ∈ O(n2 ) is true but loose. Use Θ when you can show both
    bounds.

Binary Search: Pseudocode
    function BinSearch(A, x, n)
        lo <- 0
        hi <- n - 1
        while lo <= hi
            mid <- floor((lo + hi) / 2)
            if A[mid] = x
                return mid
            else if A[mid] < x
                lo <- mid + 1
            else
                hi <- mid - 1
        return -1

Why Must A Be Sorted?
    The loop maintains an invariant:
    Invariant
    If x occurs in A, then it occurs in A[lo..hi].
       • A[mid] < x : sortedness means everything at or left of mid is < x , so discarding it
         is safe
       • On an unsorted array the same discard can throw away x

Analysis
    Basic operation: the comparison A[mid] against x .
       • Best case: x is at the first midpoint, so 1 comparison
       • Worst case: the range halves every round; let C (n) be the comparisons:
          C (n) = C (⌊n/2⌋) + 1,   C (1) = 1   =⇒    C (n) = ⌊log2 n⌋ + 1 ∈ Θ(log n)

The Sorting Problem
            Input a sequence of n items A[0..n − 1]
          Output the same items rearranged so that A[0] ≤ A[1] ≤ · · · ≤ A[n − 1]
    Two properties we will ask about every sorting algorithm:
      • in-place: uses only O(1) extra memory beyond the array
       • stable: equal keys keep their original relative order

===== w03-L1 viewer p.3 =====
The Idea: Sort a Hand of Cards
    Pick up cards one at a time. The cards already in your hand are always sorted.
       • Take the next card
       • Slide it left past every card that is larger
       • Drop it into the gap
    In an array: A[0..i − 1] is the sorted “hand”; A[i] is the next card.

===== w03-L1 viewer p.4 =====
Insertion Sort: Pseudocode
    function InsertionSort(A, n)
        for i <- 1 to n - 1
            v <- A[i]
            j <- i - 1
            while j >= 0 and A[j] > v
                A[j + 1] <- A[j]
                j <- j - 1
            A[j + 1] <- v
    The basic operation is the comparison A[j] > v.

===== w03-L1 viewer p.6 =====
Why It Is Correct
    Loop invariant
    At the start of the round for index i, A[0..i − 1] contains the original first i items in
    sorted order.
       • Initially (i = 1): a single item is sorted
       • Each round: the inner loop shifts larger items right and inserts v , so A[0..i] is
         sorted
       • At the end (i = n): the whole array is sorted
