Why Do We Care About Efficiency?
    Two ways to compute 1 + 2 + · · · + n:
   Loop                                           Formula
   add 1, 2, . . . , n one by one                 compute n(n + 1)/2
   about n additions                              one multiplication, one division
    Both are correct. For n = 109 only one of them is practical.
    Question: how do we compare algorithms without running them?

Input Size and Basic Operation
    We measure cost as a function of the input size n, counting the basic operation –
    the operation executed most often in the innermost loop.
               Problem                 Input size            Basic operation
               Search a list           number of items n     key comparison
               Multiply two matrices   matrix dimension n    scalar multiplication
               Test if n is prime      number of bits of n   division

Worst, Best and Average Case
    function find(A, x, n)
        j <- 0
        while j < n
            if A[j] = x
                return j
            j <- j + 1
        return -1
       • Basic operation: the comparison A[j] = x
       • Worst case: x is absent, so n comparisons
       • Best case: x is in the first position, so 1 comparison

Big-O: The Definition
    O(g(n)) is the set of functions that grow no faster than g.
    Definition
    t(n) ∈ O(g(n)) iff there exist constants c > 0 and n0 such that t(n) ≤ c · g(n) for all
    n > n0 .
    Example. 3n + 10 ∈ O(n).
    For n > 10 we have 3n + 10 < 3n + n = 4n, so choose c = 4 and n0 = 10.

Big-Omega and Big-Theta
       • t(n) ∈ Ω(g(n)): t(n) ≥ c · g(n) for all n > n0 – a lower bound
       • t(n) ∈ Θ(g(n)): both O(g) and Ω(g) – the exact order of growth
    Caution. Writing 3n ∈ O(n2 ) is true but loose. Use Θ when you can show both
    bounds.
