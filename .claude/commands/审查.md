# `/审查 <课程> <代号>` —— 作业交前审查

> 它是 `/作业` 会话里的一个子流程，**不是新的会话类型**：写文件只许 `<课程>/作业/` 和交接单（主 `CLAUDE.md` 写文件分区）。
> 完整设计（三档政策、镜头库、schema、核实与判官规则、40 条来源教训、**实现现状**）→ `docs/作业审查.md`。
> 记号：`D = <课程>/作业/_审查/<代号>/`，`N` = 第几轮。脚本：`T = python3 shared/工具/作业审查.py`。

可选参数：`--type report|sql|code|calc|short|model` · `--lenses a,b` / `--add x` / `--drop y` · `--shard key=a,b`（一个镜头切几片）· `--xmodel`（有 Codex 时）

---

## 0. 前提

- 不在 `/作业` 会话里 → 先照 `.claude/commands/作业.md` 第零步登记。
- 🔒 **审查不提交、不上传、不发帖**（主 `CLAUDE.md`「对外动作一律先问」）。报告里只给客观计数，**不写「可以交了 / 定稿」**。

## 1. 定档位（0 个 agent）—— 🔒 只能等于或严于分级表

1. 在主 `CLAUDE.md`「按课分级」表里找**这一份作业**那一行（不许拿同门别的作业或别门课推）：

   | 那一行写的 | 建议档位 | 选项里给什么 |
   |---|---|---|
   | 允许 AI | `allowed` | allowed · guided · forbidden |
   | 不允许 AI 产出最终件（最终产出由学生自己完成）| `guided` | guided · forbidden |
   | spec 禁止任何 AI 使用 | `forbidden` | forbidden |
   | **没有这一行（未核）** | `guided` | guided · forbidden（**没有 allowed**）|

2. 用 `AskUserQuestion` 让他确认档位（选项只列上表那一格，推荐项放第一个），一并问：
   - **作业类型**（按作答文件后缀猜：`.sql` → sql · `.java/.py` → code · 长 `.tex/.md` 报告 → report · 题号 + 推导 → calc · 简答 → short · 图 → model），让他确认
   - `guided` 档再问一句：要不要每条附一个**只含问题、不含答案**的引导问题（`hint: none | question`，默认 none）
3. 想要更宽的档 → **不在这里改**：写进交接单 `## 2`，等 `/总控` 把分级表那一行改了再审。
4. **forbidden** → `T checklist <课程> <代号> --type <类型> --spec <题面>`。零模型、零网络、不读他的作答。
   把 `D/自查清单.md` 转成 PDF（逐页看图）发给他 → **结束，不跑任何 AI 审查**。

## 2. 机械预检（0 个 agent，脚本跑）

```bash
python3 shared/工具/作业审查.py prep <课程> <代号> --round N \
    --files <作答…> --spec <题面 / 要点> [--rubric …] [--faq <官方答疑存档>] \
    [--slides <相关课件>] [--starter <起始代码>] [--reference <官方示范 / 参考>] [--raw-data <原始数据>] \
    [--no-spec-feed] [--render-pages]
```


- 冻结副本 + SHA-256 · 文字层 · `D/材料/README.txt`（写明哪些材料**没提供**，依赖它们的镜头会如实写「没查」）· `D/rN/mechanical.json`。
- 分级表写着「不许把整份 spec 喂给 AI」的作业：加 `--no-spec-feed`，`--spec` 只给 `<代号>-要点.md`（给全文会被拒）。之后每次 prep 都沿用，忘了加也一样拒；政策真的变了才用 `--allow-spec-feed`。
- 类型相关的机械步由我自己跑，结果补进 `mechanical.json`：编译两遍查 `^!` / Overfull · 真编译真运行样例 · 在临时库里真建库。
- 🔑 **补 README 的「已知且刻意」「已修」两节**：从 `<代号>-要点.md`、作答里的注释、交接单里取；拿不准的列给他勾。这一步不做，finder 会把故意的设计当 bug 反复报。
- prep 报「和第 N−1 轮的材料完全一样」→ 档位也一样就**不审**，直接给上一轮的报告（终止条件 T3；第 3 步的 `lenses` 也会拒）。换了档位照常审。
- prep 报「r N/ 和第 N 轮的报告作废」→ 正常：同一轮改了作答，旧结果和报告自动挪成 `*.stale-*`（guided 档先清洗再挪）。
- 机械结果里有 `note`（部分页没有文字层、格式不支持抽文字、空文件）→ 先处理再审，不然那部分等于没审。

## 3. 选镜头 + 问一次「开始？」

```bash
python3 shared/工具/作业审查.py lenses <课程> <代号> --type <类型> --tier <档位> [--hint question] --round N [--xmodel] [--add …] [--drop …] [--shard …]
```

输出 `lenses`（完整镜头对象）、`plannedAgents`、`manifestDigest`、`specFeedAllowed`、`knownNumbers`（guided 档）、`notes`（哪些镜头为什么没开），
并把第 1 步确认的档位写进 `D/rN/tier.json`（之后 `scrub` / `assemble` 按它取档位）。
- 同一轮换了档位 / hint / 类型：上一次的结果整批挪进 `rN.stale-*`。🔒 已经按 guided 审过的一轮**不能放宽成 allowed**（`--force` 也不行）—— 分级表真的放宽了就 `prep --round N+1` 开新一轮。
默认 = 这类作业的核心镜头（≤ 5 个）+ 满足条件的 auto 镜头（有答疑存档 → `faq-compliance`；spec 要求声明 → `declaration`，只在第 1 轮），第 2 轮起加 `regression`。
- 🔒 `manifestDigest` 是**现算的**：材料、README（含你补的两节）、`settled.json`、`镜头.json` 任何一个改了，都要**重跑一次 `lenses`** 再起 workflow，不然缓存会用旧结果。

- 规模：目前只实现了 standard（≈ 8–10 个 agent，≈ 1.3–2.6 M token，20–40 分钟）。想轻就 `--drop`；想加镜头超过 10 个 → 🔒 **要他单独同意大规模，并在他不学习的时候跑**，args 里给 `largeApproved: true` 和对应的 `maxAgents`。
- 🔒 **问一次**：「档位 X · 类型 Y · 镜头 [..] · N 个 agent · ≈ T token · ≈ M 分钟 · 开始？」—— **他说开始才起**（主 `CLAUDE.md`：任何 Workflow 先问）。
- 写 `D/运行记录.md`：档位、类型、镜头、agent 数、开跑时间、续跑命令。

## 4. 跑 workflow

```
Workflow({
  scriptPath: "<项目根>/.claude/workflows/assignment-review.js",
  args: {
    root: "<项目根绝对路径>", course, code, round: N, type,
    tier: "allowed" | "guided", tierConfirmed: true, hint: "none" | "question",
    lenses: <第 3 步输出的 lenses>,                 // workflow 读不了文件，镜头定义要整份塞进来
    manifestDigest: <第 3 步输出的 manifestDigest>,  // 进每个缓存键：材料、README 手写节、settled、镜头.json 一变，所有阶段都重做
    specFeedAllowed: <第 3 步输出的 specFeedAllowed>,
    knownNumbers: <第 3 步输出的 knownNumbers>,      // 只有 guided 档有；用来查「作答和规则里都没有的新数字」
    scratch: "<scratchpad 目录>/review-<code>-rN",
    xmodel: <codex 已装且他同意 ? true : false>     // 只接受 true / false
  }
})
```

- 可以先加 `dryRun: true` 看计划（不起 agent）。
- 撞限额：`TaskStop` → `Workflow({scriptPath, args, resumeFromRunId})`；换了会话就用同一份 args 重跑（每个 agent 先落盘，输入没变的秒过）。
- workflow 报「材料在 prep 之后被改过」→ 重新 prep 再跑。报「所有镜头都没跑成」→ 不出报告，查原因再跑。

## 5. 收口

1. 🔒 **guided 档先清盘再看报告**：
   ```bash
   python3 shared/工具/作业审查.py scrub <课程> <代号> --round N   # 清 rN/ 和 rN.stale-*/ 的 JSON，再扫报告；退出码 1 = 报告里还有疑似答案的行
   python3 shared/工具/作业审查.py scan <D>/报告-rN.md --course <课程> --code <代号>
   ```
   scrub / scan 列出的行 → 删掉或改写（scrub 不会偷偷改报告），再 scan，**过了才往下走**。
2. `D/rN/judge.json` 或 `D/报告-rN.md` 不在（判官挂了）→ `python3 shared/工具/作业审查.py assemble <课程> <代号> --round N`（档位按 `rN/tier.json`），用 `D/报告-rN-原始.md`；guided 档同样先 scan。
3. 看 workflow 返回值：`missingFinders` 非空 / `xmodelState` 是 `failed` / `judge.mismatch` 为 true（`unknownIds` 判官编了不存在的编号 · `missingIds` 漏分了 · `classConflict` 把票没收齐的判成必改）→ 在对话里明说「结论不完整」及原因。`renumbered` 为 true → 跑 `python3 shared/工具/作业审查.py fix-ids <课程> <代号> --round N`，把盘上 `merged.json` 的编号对齐（guided 的 scrub 和 assemble 也会顺手做）。
4. **必改项我自己再开证据看一遍**，再把报告转 PDF，逐页看图后发给他。对话里只留两三句：必改几条 · 最要紧的一条在哪 · 要他拍板什么。
5. 把 `rejected` / `leave` / 改完的 `fixed` 追加进 `D/settled.json`：`{"rejected": [...], "leave": [...], "fixed": [...]}`，每条 `{"title": "…", "reason": "…", "round": N}`（按标题匹配，不用 F 编号）。下一轮不再重开。

## 6. 他决定改哪些

| 档位 | 怎么改 |
|---|---|
| `allowed` | `AskUserQuestion` 多选挑补丁，再问「我改 / 你自己改」；我改的改完跑机械回归（编译 / 运行 / 页数）|
| `guided` | **他自己改**。我只重跑机械检查，和下一轮审查 |

## 7. 下一轮还是停

满足任一就停：本轮核实后没有新的必改和值得改 · 跑满 3 轮 · 材料和档位都和上一轮一样（直接给上一轮报告）·
本轮必改全是上一轮改动引入的回归（修完只跑机械回归）· 离截止不到 6 小时（只跑机械检查）· 他说停。

继续 → 改完后 `prep --round N+1`（README 会自动带上改动 diff 和 settled）→ 回到第 3 步。

结束时：在本会话交接单的 `## 4` 记一笔审查结论摘要；spec 要求 AI 声明的，把「用了 AI 审查」写进交付清单（`allowed` / `guided` 都要如实写）。

## 不用 Claude Code？

同一套设计的简化版（任意 OpenAI 兼容模型，见 `docs/接入其他模型.md`）：

```bash
python3 shared/工具/作业审查.py prep <课程> <代号> --files … --spec …
python3 shared/工具/作业审查.py run <课程> <代号> --type <类型> --tier guided --confirm-tier guided [--round N]
```

它不运行代码、不看图片，报告顶部会写明做不到的部分。guided 档落盘前就会拿掉疑似答案的发现；发报告前同样跑一遍 `scan`。
