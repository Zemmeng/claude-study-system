# 作业交前审查（`/审查`）—— 设计说明

> 实现：`.claude/commands/审查.md`（流程）· `.claude/workflows/assignment-review.js`（Claude Code workflow）· `shared/工具/审查镜头库.json`（镜头库）· `shared/工具/作业审查.py`（机械预检 / 自查清单 / 任意模型的简化版）。
> 来历：从原作者一个学期里 5 套真实的交前多 agent 审查提炼而来，下文用来源 key 标注：`db-a1`（数据库建模报告）· `net-p1`（网络实测报告，含 Codex 互审）· `prog-a1`（Java 代码）· `db-a2`（SQL，四轮）· `rules`（散在规则档案里的教训）。不含任何具体作业内容。
> 测试：`node tests/workflow_harness.mjs`（编排逻辑，离线）· `python3 tests/review_test.py`（Python 版，假模型服务器）。

---

## 0. 一句话

**交前审查 = 机械预检（零 agent）→ 按镜头并行找问题 → 合并去重 → 对抗式核实 → 一个判官分级出报告 → 学生决定改不改 → 只审差异，最多 3 轮。**
它是 `/作业` 会话里的一个子流程，**不是新的会话类型**；按那份作业自己的 AI 政策分三档（`allowed` / `guided` / `forbidden`），档位由学生在开跑前确认，**只能等于或严于主 `CLAUDE.md` 分级表那一行，绝不自动放宽**。

为什么要固化：原来 5 套审查都是每份作业在对话里临时写一个 `workflow.js`，规则散在 `CLAUDE.md`、工具手册、`codex.md` 和几条记忆里，换一份作业就得从头再写一遍（`net-p1` · `prog-a1` · `rules`）。现在收成一个命令 + 一个保存的 workflow + 一个与模型无关的 Python 工具 + 一份镜头库。

## 0.5 实现现状（以这一节为准）

| 已实现 | 说明 |
|---|---|
| 三档政策 + 档位闸门 | workflow 和 Python 两边都拒跑 `forbidden`、拒跑未确认的档位 |
| `standard` 规模 | 每类作业的 **core** 镜头（≤ 5 个）+ 满足条件的 **auto** 镜头（`faq-compliance` 有答疑存档时、`declaration` spec 要求声明时），默认 ≤ 10 个 agent；重跑也计入上限 |
| 缓存按输入指纹 | 输入指纹 = 材料（含角色）+ README（含学生手填的两节）+ `settled.json` + `镜头.json`，由 `lenses` 现算成 `manifestDigest`。workflow 的 find / merge / facts / marker / judge 每个缓存键都带它和档位、hint、轮次、类型，agent 返回的 `input_key` 不对就当没结果重跑；Python 的 `_fp` 另含模型名和字数上限。同一轮重新 `prep` 且材料变了，旧的 `rN/` 和这一轮的报告挪成 `*.stale-*`（guided 先清洗再挪）|
| guided 防泄漏 | 白名单字段（含 `location` / `rule_source` 的子键）→ 逐字段 LEAK 正则 + 「新数字」（作答、spec / faq / rubric、README、机械检查里都没有的数；行号、页码、字数、哈希这类结构化记号先去掉）→ 只豁免能逐字核实的引用 → 判官看不到核实员的理由，coverage / not_checked 带答案的整条丢 → `scrub` 清盘（白名单 + 递归扫描 + 引文逐字核实，含 `rN.stale-*`）并扫报告 → `scan` 发前检查（围栏 / 缩进代码块整段算命中，`#` 和 `⚠️` 行照扫）|
| 子命令 | `prep` · `lenses` · `checklist` · `scrub` · `scan` · `assemble` · `run` |
| 测试 | `tests/workflow_harness.mjs`（编排，离线）· `tests/review_test.py`（Python 版，假模型服务器），都进 CI |

| 规划中（还没实现）| 现在怎么办 |
|---|---|
| `lite` / `deep` 规模档 | 想轻：`--drop` 去掉镜头；想重：`--add` 加镜头 + 学生单独同意大规模（`largeApproved`）|
| 自定义跨模型 CLI（`xmodel` 传对象）| 只支持 Codex：`xmodel: true`；传对象会直接报错 |
| 「缺票只重跑那一票」| 没结果或回票不全的批次整批重跑一次（预算内），仍缺记 `incomplete`；Python 版回票不全的批次不当缓存，下次补 |
| 每轮最多 3 轮、离截止 < 6 h 只跑机械检查 | 由 `/审查` 的主会话判断（第 7 步），代码不强制 |
| Codex 每份作业 ≤ 2 次 | workflow 只保证一轮里 xmodel 失败不重跑；跨轮次数由 `/审查` 的主会话记在 `运行记录.md` 里自己数 |

## 1. 与模板现有规则的对齐

| 模板规则（出处） | 本设计怎么遵守 |
|---|---|
| 「每份作业的 AI 条款以那份作业自己的 spec 为准」+ 分级表是唯一出处（主 `CLAUDE.md`「学术诚信」节；`作业.md` 第一步） | `/审查` 不自己判政策，**只读分级表那一行**给出建议档位；没有那一行 = 「未核」= 最多 `guided` |
| 「未核的一律按最严的走：不代写、只审查」 | 未核时选项里**没有** `allowed` |
| 不允许 AI 的作业：「指出他哪一步错了、哪里不严谨（但不说正确的是什么）」「不替他写英文句子」 | `guided` 档的 finding schema **没有改法字段**，外加四层泄漏过滤（§7.2） |
| 「能引导到哪一步以那份 spec 为准、由他定」 | `guided` 档有子选项 `hint: none｜question`，默认 `none`；不再往上放 |
| 分级表写着「不许把整份 spec 喂给 AI」的作业只读 `-要点.md` | 材料清单里 `spec_feed_allowed=false` 时**不拷 spec 全文**，只拷 `-要点.md`；Codex 同理 |
| 「提醒过一次后不再劝」「不许开调查」 | 审查不评政策本身；声明镜头只查「声明与实际使用记录是否一致」 |
| `/作业` 会话**只写 `<课程>/作业/`** + 交接单（写文件分区） | 全部落盘在 `<课程>/作业/_审查/<代号>/`；要动账本的写进交接单 `## 2` |
| 「> 10 个 agent · **任何 Workflow** 先问，预约制，他不学习时跑」（主 `CLAUDE.md` 大规模 subagent 节） | `/审查` 启动 workflow 前**必问**一次（含 agent 数、token 估计、预计时长）；默认档 ≤ 10；> 10 要单独的「大规模」同意 |
| 「扇出一律 `model: 'sonnet'`，主模型只给 1–2 个 judge」 | 脚本里**每个** `agent()` 显式写 `model`；只有判官继承主模型 |
| 「每个 agent 先落盘再返回」（`工具手册.md` 落盘节） | 每个 agent 开工先查自己的输出文件、做完先 Write 再返回 |
| 「对外动作一律先问」「不许替他说定稿」 | 审查不提交、不上传；报告只给客观状态（「剩 N 条必改」），**不出现「可以交了」** |
| 对话里表格 ≤ 4 列；PDF 发前逐页看图 | 对话只留两三句；细表进报告 PDF；PDF 走模板的视觉检查流程 |
| `shared/API笔记/codex.md` 的配方与「Codex 只跑 1–2 次」 | 跨模型可选，每份作业累计 ≤ 2 次，没装就跳过 |

## 3. 总流程（文字流程图）

```
/作业 会话里，他说「审一下 / 交前查一遍」或打 /审查 <课程> <代号>
│
├─ S0 档位确认（主会话，0 agent）
│    读主 CLAUDE.md 分级表那一行 → 建议档位
│    AskUserQuestion：只列「建议档位 + 更严的档」（未核：guided / forbidden）
│    ├─ forbidden ──▶ python3 shared/工具/作业审查.py checklist … （零 LLM）
│    │                 → 自查清单.md/.pdf 发给他 → 结束（不跑任何 AI 审查）
│    └─ allowed / guided ▼
│
├─ S1 机械预检（主会话 + 脚本，0 agent）            prep 子命令
│    冻结快照 + SHA-256 → 材料/README.txt（权威顺序 · 已知且刻意 · 已修 · settled）
│    编译 / 运行 / 建库 / 页数字数 / ^! 与 Overfull / 文字层索引 / 页面 PNG（按需）
│    机械检查发现的问题直接进 r{N}/mechanical.json，不交给 agent
│
├─ S2 计划 + 问一次（主会话）
│    「档位 X · 类型 Y · 镜头 [..] · N 个 agent · ≈ T token · ≈ M 分钟 · 开始？」
│    N > 10 → 额外要「大规模」同意；建议在他不学习时跑
│    填 运行记录.md（runId 待回填、续跑命令、预期产物清单）
│
├─ S3 Workflow assignment-review.js（一轮）
│    ┌ Find：k 个 finder（sonnet）并行   ∥  0–1 个 codex-runner（sonnet，壳里调 codex exec）
│    │      每个先查 r{N}/find-<lens>.json 在不在 → 在就读回；不在就做 → Write → 返回
│    │      JS：核「期望文件数 = 收到数」，缺的重跑一次；仍缺 → 记 missing，不静默
│    ├ Merge：1 个（sonnet）去重 · 剔除 known/fixed/settled · 核引文逐字存在 · 编号 F01…
│    │      → r{N}/merged.json（原始清单先落盘，判官挂了也不丢）
│    ├ Verify（自适应，批处理）
│    │      facts 镜头（sonnet，默认 keep=false）→ 只有 keep 的进
│    │      marker 镜头（sonnet；allowed 档同时做 fix-safety）
│    │      polish 级不核实，直接标 unverified 进「可选」
│    │      → r{N}/verify-<lens>-b<i>.json
│    └ Judge：1 个（主模型）复现每条必改 · 分级 · 写 not_covered · 出报告
│           → r{N}/judge.json + 报告-r{N}.md
│
├─ S4 主会话收口
│    judge.json 缺 → `作业审查.py assemble` 从盘上 JSON 机械拼原始报告
│    必改项主会话自己开证据再看一遍 → 报告转 PDF（逐页看图）→ 发给他
│    对话只留 2–3 句：必改几条、最要紧的一条在哪、要他拍板什么
│
├─ S5 他决定改哪些
│    allowed：多选挑补丁 + 问「我改 / 你自己改」→ 改完跑机械回归
│    guided ：他自己改；我只重跑机械检查
│
└─ S6 终止判断（§10）── 继续 → 下一轮只审差异（regression 镜头必开）
                       └─ 停 → 交接单记一笔（声明要点 / 操作清单），结束
```

## 4. 各阶段明细

记号：`D = <课程>/作业/_审查/<代号>/`，`N` = 轮次。

| 阶段 | agent 数 | 模型 | 输入 | 输出 / 落盘 |
|---|---|---|---|---|
| **S0 档位确认** | 0 | 主会话 | 主 `CLAUDE.md` 分级表那一行 · `<课程>/CLAUDE.md` 的补充 | 确认的档位由 S2 的 `lenses`（或 Python 的 `run`）写进 `D/r{N}/tier.json`（`tier`、`hint`、`type`、`at`）；`运行记录.md` 首行 |
| **S1 机械预检** | 0 | 脚本（`作业审查.py prep` + 类型相关命令） | 当前作答文件、spec / `-要点.md`、rubric、官方答疑存档、课件文字层 | `D/材料/`：冻结副本 · `MANIFEST.json`（每文件 SHA-256 + 角色）· `README.txt` · 文字层 · 页面 PNG（`--render-pages` 时渲染作答 PDF 的全部页，每次 prep 重渲）· `D/r{N}/mechanical.json` · `D/r{N}/manifest.json`（本轮材料指纹）· `D/r{N}/snap/`（本轮作答文字快照，下一轮的 diff 和它比）|
| **S2 计划** | 0 | 主会话 + `作业审查.py lenses` | 镜头库 + 类型 + 档位 | `lenses` 输出 workflow 的 args 片段并写 `D/r{N}/tier.json`；`运行记录.md`：配置、agent 数、token 估计、续跑命令、预期产物清单 |
| **S3a Find** | 默认 4–6 | **sonnet** | `README.txt` + 镜头 prompt + 材料绝对路径 | `D/r{N}/find-<lensKey>.json` |
| **S3a′ 跨模型（可选）** | 0–1 runner | runner 用 **sonnet**；实际审查是 Codex | `材料/` 的隔离副本（按档位裁剪）+ README | 原始输出留在 `{scratch}/xmodel/`（不进学生目录）+ `D/r{N}/find-xmodel.json`（runner 转成同一 schema）；没装 → `aborted: "skipped: …"` |
| **S3b Merge** | 1 | **sonnet** | finder 的发现（编排层先白名单 + 扫描，再直接写进 prompt，不让 merge 去读盘上的原文）+ `README.txt` + `settled.json` | `D/r{N}/merged.json` |
| **S3c Verify-facts** | 1–2（每批 ≤ 10 条） | **sonnet** | merged 条目（只给 claim，不给 finder 的 confidence）+ 材料 | `D/r{N}/verify-facts-b{i}.json` |
| **S3d Verify-marker(+fix)** | 1（只核 facts 留下的） | **sonnet** | facts 留下的条目 + rubric + 官方答疑 | `D/r{N}/verify-marker-b{i}.json` |
| **S3e Judge** | 1 | **主模型**（不写 `model` = 继承；或 `args.judgeModel`） | merged + 全部 verdict + mechanical + settled | `D/r{N}/judge.json` + `D/报告-r{N}.md` |
| **S4 收口** | 0 | 主会话 | 上面全部 | `D/报告-r{N}.pdf`；`D/settled.json` 累加（rejected / leave / fixed） |

**默认规模（standard 档）**：≤ 6 finder（core ≤ 5 + 预算内的 auto）+ 1 merge + 1 facts + 1 marker + 1 judge ≤ **10**；开 Codex 时 finder 上限降到 5 → 仍 ≤ 10。
**其他档**：

| 规模档 | 组成 | agent 数 | 要不要额外同意 |
|---|---|---|---|
| `lite`（规划中）| 3 finder + merge&facts 合一 + judge | 5 | 只问一次「开始？」 |
| `standard`（默认） | 见上 | 9–10 | 只问一次 |
| `followup`（第 2/3 轮） | regression + 被改动区域相关的 2–4 个镜头 + merge + facts + judge | 5–8 | 只问一次 |
| `deep`（规划中）| 8–13 finder · 每条 facts 两票（不同镜头）· marker · fix · Codex 批量裁决 | 20–40 | 🔒 **大规模同意 + 预约**，他不学习时跑 |

`/审查` 在 S2 算出 `plannedAgents`，workflow 里再算一遍：`> args.maxAgents（默认 10）且 !args.largeApproved` → **直接 throw，不起任何 agent**。

## 5. 默认镜头库（`shared/工具/审查镜头库.json`）

### 5.1 每个镜头的字段

```json
{
  "key": "spec-compliance",
  "title": "spec / 提交规则合规",
  "types": ["*"],
  "tiers": ["allowed", "guided"],
  "rounds": "first",               // first | all | followup（对 core 和 auto 都生效；--add 显式点名的不受限）
  "needs": ["read"],               // read | run | db | images | raw-data
  "core": ["report","sql","code","calc","short","model"],   // 这些类型默认就开（每类 ≤ 5 个）
  "optional_for": [],              // 只能 --add 打开
  "auto": false,                   // true = 满足 requires 就自动开（预算内）
  "requires": {},                  // {"roles": ["faq"]} 或 {"spec_regex": "…"}
  "limits": {},                    // {"render_pages": 3, "tool_calls": 25}
  "max_findings": 6,
  "prompt": "……本镜头的步骤化任务（见 5.4 的写法）……",
  "self_check": ["forbidden 档自查清单里的一条"]
}
```

调用者覆盖：`/审查 … --lenses a,b,c`（整组替换）· `--add x` · `--drop y` · `--shard key=a,b`（一个镜头切成几片并行，例：代码按模块切）· `D/镜头.json`（自定义镜头，同字段；同 key 覆盖库里的那项，没写的字段沿用库里的；新镜头必须有 key / title / types / tiers / prompt，要默认开就写 `core`；JSON 写错直接报错带行号）。`/审查` 合并后把**完整镜头定义**塞进 workflow `args.lenses`（workflow 自己读不了文件）。`needs` 里有 `run/db/images` 的镜头在 Python 简化版里自动降为「静态推理」并在报告里标出。

### 5.2 通用镜头（所有类型）

| key | 查什么 | 默认 |
|---|---|---|
| `spec-compliance` | 非内容规则：文件名、页数/字数、字号行距、署名、必交文件、提交方式、迟交罚则、声明是否存在 | ✅ 第 1 轮 |
| `rubric-marker` | 把 rubric / spec 每句拆成独立得分点，逐点判：显式回答？对？有证据？深度？没注水？只报会丢分的点（暂定分区间由判官统一给）| ✅ |
| `faq-compliance` | 官方答疑 / 教职员帖逐条：要求、澄清、许可、禁止；**只认教职员，不认同学** | ✅（有答疑存档时） |
| `minimal-form` | 🔑 每个题面没要求的构造（多余条件、多余连接/实体/分支、防御性冗余、超纲写法）问「课上示范或官方解答里有吗？没有就默认是成本，除非能说出它防住的具体失败」 | ✅ sql / calc / short / model（code 可选）|
| `declaration` | 声明文字 vs 实际 AI 使用记录（`.tex` 注释 / `<代号>-AI使用记录.md`）是否如实、完整；**不评政策本身** | ✅（spec 要求声明时） |
| `adversary` | 扮严格阅卷人想办法扣分，每项写「规则 → 证据 → 阅卷人会怎么扣」（概率和期望损失由 marker 判）| 可选（`--add`）|
| （critic，判官兼任，不是独立镜头）| 读完所有报告后找「谁都没查过的」，尤其文件之外（新的官方帖、平台设置、提交后状态） | 判官的 `not_covered` / `operations_checklist`；standard 档由判官兼任 |
| `regression` | 上一轮之后的改动：有没有打坏句子/行为、与别处矛盾、证据不再支撑、悄悄丢掉得分点、对冲过头不下结论 | ✅ 第 2 轮起必开 |

### 5.3 按作业类型（以 `审查镜头库.json` 的 `core` / `optional_for` 为准）

| 类型 | 核心镜头（默认就开，≤ 5 个）| 可选（`--add`）|
|---|---|---|
| **report**（长报告/实测报告） | `spec-compliance` · `rubric-marker` · `technical` · `numbers` · `evidence` | `adversary` · `figures` · `citations` · `language` · `cross-ref` |
| **sql** | `spec-compliance` · `rubric-marker` · `minimal-form` · `semantic` · `deliverable-consistency` | `adversary` · `env` · `blind-solve` · `ddl-silent` |
| **code** | `spec-compliance` · `behaviour` · `hidden-tests` · `presentation` · `scope-forbidden` | `rubric-marker` · `minimal-form` · `adversary` · `env` · `structure` · `style-consistency` |
| **calc**（计算/推导题） | `spec-compliance` · `rubric-marker` · `minimal-form` · `per-question-check` | `adversary` · `blind-solve` |
| **short**（简答/justify） | `spec-compliance` · `rubric-marker` · `minimal-form` · `per-question-marker` | `adversary` · `language` · `blind-solve` |
| **model**（建模/图） | `spec-compliance` · `minimal-form` · `rules-coverage` · `keys-relations` · `diagram-consistency` | `rubric-marker` · `adversary` · `ddl-silent` |

所有类型另有两个 **auto** 镜头：`faq-compliance`（材料里有官方答疑存档时自动开）、`declaration`（spec 里要求声明时自动开）—— 排在核心镜头之后，超出默认预算就跳过并说明。第 2 轮起自动加 `regression`。
`blind-solve` 只在 `allowed` 档能跑（它会在盘上生成一份完整解答）。

报告类的分支镜头说明（摘要）：
- `technical`：逐个技术断言尝试反驳；**因果是否被测过还是写成定论**。
- `numbers`：🔒 **用原始数据当 ground truth**，写脚本重算均值、倍数、单位换算；只对派生表核 = 循环论证（`net-p1`）。
- `evidence`：正文每个具体数字/字符串在被引截图里是否真的可见；抽查 ≥ 20 张（真读图）。
- `language`：allowed 档给同长或更短的改写；guided 档只标位置和问题类别。

### 5.4 finder prompt 骨架（公共前缀 COMMON + 镜头段 + 落盘段）

```
【角色】严格但公平的阅卷人，在提交前预审。第 {N} 轮。
{N>1: 你的价值只在「前几轮漏掉的」和「前几轮改动自己引入的错」。}
【先读】{D}/材料/README.txt —— 权威顺序、已知且刻意（不许报）、已修（不许重报，除非修复本身错了）、
       settled（已裁定，无新证据不得重开）。
【开工校验】sha256sum 你要审的文件，对 MANIFEST.json；不一致 → 立即返回 {aborted:"hash-mismatch"}。
【证据纪律】
  · 每条 finding 必须带：作答原文逐字引文（≤ 200 字符）+ 精确位置（文件:行 / 页）+ 规则原句与出处。
  · 不许发明要求；规则只认 README 里列为「权威」的文件。
  · 返回前自检：「阅卷人真的会因此扣分吗？官方答疑有没有相反说法？这是可辩护的设计选择吗？」答不上来就别报。
  · 最多 {max_findings} 条，按风险排序；零条是合法答案。必须写 checked_ok[]（查过且没问题的）和 not_checked[]。
【工具纪律】只读；临时文件只放 {scratch}/{lensKey}/；不连任何远程服务；不整份提取长 PDF（用 材料/ 里的文字层与页码索引），
           渲染页面 ≤ 3 页；工具调用 ≤ 25 次。
【档位】{tier 段，见 §7}
【本镜头】{lens.prompt}
【落盘 —— 返回前必须做】
  1. 开工前先看 {D}/r{N}/find-{lensKey}.json：存在、是合法 JSON、且 input_key 等于这次的键 → 直接读出来原样返回，不重做；
     键不一样或不存在 → 输入变了，重做。
  2. 做完先用 Write 把将要返回的**完全相同**的 JSON（带 input_key）写到该路径，再返回。
     写文件只许写它和 {scratch}/{lensKey}/ 下的临时文件。
```

## 7. 三档政策的行为差异

### 7.1 总表

| | `allowed` | `guided` | `forbidden` |
|---|---|---|---|
| 何时可选 | 分级表那一行是「允许 AI」 | 那一行是「不允许 AI 产出最终件」，**或未核** | 那一行写「spec 禁止任何 AI 使用」；任何档的人都可以主动选它 |
| 跑 AI 审查 | ✅ | ✅ | ❌ **一个 agent 都不起，不调任何 API** |
| 材料 | 全套 | 全套；`spec_feed_allowed=false` 时只给 `-要点.md` | 不读他的作答内容 |
| 镜头 | 全库 | 去掉 `blind-solve`（会在盘上生成一份完整解答）· `language` 只标位置 | — |
| finding 字段 | 含 `suggested_fix` / `old_text` / `new_text` / `adds_lines` | **只有位置 + 规则 + 哪里不对 + 为什么扣分**；`hint=question` 时可加一个不含答案的问题 | — |
| 核实镜头 | facts → marker+fix | facts → marker（**无 fix 镜头**） | — |
| 跨模型 | 可选（默认关；他同意、且装了 Codex 才开） | 同左；开的话同样过泄漏过滤 | — |
| 报告 | 必改项附 OLD/NEW 补丁（主会话重写过措辞） | 必改项只有位置、原因、规则原句；顶部一行写「⚠️ 按这份作业的 AI 政策，本报告只指出位置和原因，不含改法。」 | `自查清单.md/.pdf` |
| 谁改 | 他挑补丁；问「我改 / 你自己改」；主会话改完跑机械回归 | **他改**；我只重跑机械检查和下一轮审查 | 他自己 |
| 声明 | `declaration` 镜头核「如实、完整」；本次审查本身也写进 AI 使用记录 | 同左 | 清单里提醒「按 spec 写声明」 |
| Python 简化版 | 同 | 同 | `checklist` 子命令，零网络调用 |

### 7.2 `guided` 的四层泄漏防线

1. **schema 层**：结构化输出里没有改法字段，`additionalProperties:false`。
2. **prompt 层**：「`what_is_wrong` 可以说哪一步推不出、与哪条规则冲突、属于哪类错误；**不许写出正确的值、表达式、句子或代码**，也不许用『应该是…』『改成…』『should be』」。照模板「不说正确的是什么」那条。
3. **机械层**（workflow 的 `scrub()` 和 Python 的 `scrub()`，两边的 `LEAK` 正则一字不差，测试会比对）：
   - **白名单**：只留认识的字段，其他一律丢；
   - **LEAK 正则**逐字段扫 title / what_is_wrong / why_it_costs / guiding_question / **evidence** / `location.question` / `rule_source.doc`·`locator`：代码围栏、「应该是 / 应当 / 改成 / 建议换成 / 把…写成 / 正确答案是 / 答案：/ 结果为 24」、「should be / should the X be / instead of / in place of / replace … with / did you mean / the answer is / answer:」、`→ "…"`、`-> 24` 等；「把应用层写成了 app 层」这类描述学生错误的说法不算；
   - **只豁免能逐字核实的引用**（Python 版）：引号里的文字能在作答或 spec / faq / rubric 里逐字找到，或命中所在的整段（≥ 20 字符，而且一直到分句末尾 —— 「Replace … with datagram」只有前半句是 spec 的不算）就是规则原文 —— 不再按 `rule_quote` 字段豁免（finder 可以把泄漏句同时填进 `rule_quote` 来洗白）。workflow 版不豁免：复述规则的说法交给 merge 改写；
   - **新颖数字**：作答、spec / faq / rubric、README、机械检查里都没出现过的数（例：算出来的 24,000）→ 判为疑似答案；slides / reference / starter 里的数不算「已知」（那里面可能就是答案）。检查前先去掉结构化记号（sha256、`文件:行`、`p.12`、`第 150 行`、`135 words`、`期望损失 ≈ 2.7 分`……）。workflow 版用 `lenses` 输出的 `knownNumbers`；
   - 编排字段（`id` / `lens` / `source` / `fix_note` / `merged_from`）只能由脚本写，模型填的一律丢掉；guided 档里只出自课件 / 参考答案 / 起始代码的原句，盘上也不留（只留出处）；
   - 命中 → `leak_suspect`：workflow 交给 merge 改写，改写不了丢弃；Python 版落盘前直接拿掉（引文对不上的也一样），只记原因（`dropped_pre`）；
   - 正则都有长度上限（防止超长空白、超长数字串把检查拖死）；两边都先做 NFKC（全角数字归一），Python 用 `re.A`，和 JS 的 `\d` `\s` 语义一致；
   - 核实员的 `reason` / `evidence_checked` 命中的换成「已隐去」；**判官只看得到核实的数值和结论，看不到理由和证据**；
   - merge 还要核：`rule_quote` 在权威文件里逐字存在、任何 > 3 个词的引号内文字是作答或权威文件的逐字子串。
   - guided 档的报告里，规则原句只在出自 spec / 官方答疑 / rubric、且能在那几类文件里逐字找到时才回显；出自课件、参考答案、起始代码的只写出处（「原句见材料」）。
4. **判官 + 主会话层**：判官 prompt 里带档位约束，落盘前通读删答案；`/审查` 收口时先 `作业审查.py scrub`（清盘 + 扫报告，不偷偷改报告），再 `作业审查.py scan`，**scan 不过不许发**。scan 逐行扫：围栏和缩进代码块整段算命中；`#` 标题和 `⚠️` 行照扫，只豁免几条固定说明行；以「档位：」「模型：」开头的抬头行只查措辞，不查文件名、模型名里的数字。

### 7.3 档位确认的硬规则

- `/审查` 用 `AskUserQuestion`，选项**只有**：分级表建议档 + 更严的档。未核 → 只有 `guided` / `forbidden`。
- 想要更宽的档 → 不在这里改：写进交接单 `## 2`，等 `/总控` 把那一行并进主 `CLAUDE.md` 分级表后再跑。
- 确认结果写进 `D/r{N}/tier.json`（由 `lenses` / `run` 写）与 `运行记录.md`。同一轮换了档位 / hint / 类型 → 上一次的结果整批挪进 `rN.stale-*`；🔒 按 guided 审过的一轮不能在同一轮放宽成 allowed（`lenses` / `run` / `assemble` 都拒绝），要开新一轮；`assemble` / `scrub` 按它取档位，没有就按 guided。workflow 校验 `args.tierConfirmed === true` 且 `args.tier ∈ {allowed, guided}`，否则 throw。
- 一次确认只管这一份作业的这一次审查（下一轮沿用，换作业重问）。

### 7.4 `forbidden` 自查清单的内容

全部由脚本按模板生成，**不调 LLM**：
1. 从 `-要点.md` / spec 里**脚本可抽取的硬性条款**（页数、字数、文件名、必交物、迟交规则）——抽取用正则 + 他确认；抽不出就留空格子给他填。
2. 该类型的通用自查项（镜头库每个镜头的 `self_check` 字段，例：「每个题面没要求的构造，课上示范过吗？」「问 why 的题，我答的是 why 还是 what？」）。
3. S1 机械预检结果（编译、页数、字数、文件名）—— 这是脚本，不是 AI。
4. 交前操作清单（提交按钮语义、平台设置、提交后不要再动的状态）。

## 8. 核实与判官规则

### 8.1 Merge（sonnet，1 个）

- 先核 `expected_finders == received_finders`，缺的写进 `missing_finders`（**不静默按少的跑**，`net-p1`）。
- 剔除：命中 known / already-fixed / settled 的；纯口味的；`work_quote` 在作答里 grep 不到的；`old_text` 不唯一的（allowed）；页数已满还要加长且说不出砍哪里的。每条写一行理由进 `dropped`。
- 合并：同一文件 + 位置重叠 + 同一底层问题 = 一条；`raised_by` 计数；保留最强 severity、最具体修法、证据取并集。
- pass 项压成 `coverage`，不当 finding（`db-a2`：152 条原始里 125 条 pass）。
- 只合并，不评判对错。

### 8.2 自适应核实（替代固定 3 票）

```
对每个 item（severity ∈ {zero, deduct, risk}；polish 跳过 → unverified）:
  facts（默认 keep=false）：亲自打开一手证据；数字类用脚本重算；行为类自己重跑；
                         只凭 finder 转述 → keep=false
     ├─ keep=false → rejected（一行理由进 settled，防下轮重报）
     └─ keep=true  → marker：假设属实，阅卷人会不会扣、扣多少、p_deduct；
                     无规则支撑的推测 → 判不扣
                     allowed 档同时 fix 检查：old_text 恰好一次 · 改后仍回答 spec 那句 ·
                     仍下结论没对冲掉 · 不更长 · 不与别处矛盾 · 标记/代码仍编译；不安全写 better_fix
          ├─ keep=true  → 候选 must_fix / should_fix
          └─ keep=false → leave（理由必填）
缺票（批次没结果或回票不全）→ 整批重跑一次（预算内），仍缺 → incomplete；**绝不算驳回**（db-a1）
```

- 每个 verifier 批 ≤ 10 条（`rules`：单核实员 ≤ 30 条够用；这里取 10 保独立和上下文）。
- verifier **不看**同伴结论、不看 finder 的 confidence；看 claim + 材料。
- verifier 不读全套材料（`db-a1`：缓存读取巨大）：workflow 版在提示里要求「只打开和这几条有关的部分」；Python 版只给 README + 权威文件 + 本批每条前后 8 行的作答片段（权威文件优先占预算）。
- `deep` 档：facts 每条两票（引文核对 / 字面核对两个镜头），两票都 keep 才进 marker。

### 8.3 判官（主模型，1 个）

1. **每条候选必改自己复现**（重跑、重渲染、量坐标、开原文）；复现不了 → 降为 should_fix 或 leave。
2. 分级：
   - `must_fix`：facts✓ + marker✓ + severity ∈ {zero, deduct}（或 risk 且 `expected_loss` 高）
   - `should_fix`：facts✓ + marker✓ 但只是 risk/小分，**且修法便宜**
   - `leave`：facts✓ marker✗，或修法成本高于期望损失 —— **理由必填**
   - `rejected` / `unverified` / `incomplete` 照 8.2
3. 排序键：`expected_loss = marks_at_risk_adjusted × p_deduct`（verifier 修正值优先于 finder 自报），再看 `raised_by ≥ 2` 和跨模型同时命中（最强信号），再看修法成本。
4. **修法成本**：需要重新取证（重上服务器重跑、重截图、重导出图）= high —— 只为零分 / 百分比罚分风险值得（`db-a2`）。
5. 🔒 `raised_by ≥ 2` 但因成本高被判 leave 的 → 报告里把「期望损失」和「改动成本」并排写，**让他知情地选**（`rules`：恰好在这里被扣分）。
6. 跨模型重复的同一问题合并计一次，计分前先去重（`prog-a1`）。
7. 写 `not_covered`（兼任 critic）和 `operations_checklist`。
8. 暂定分只给**区间**并写 caveat（`net-p1`：不同 agent 浮动 0.5–1 分）。
9. 判官对被审文件只读。

### 8.4 跨模型互审（可选）

- 由一个 **sonnet runner agent** 执行（workflow 本身不能跑命令）：`command -v codex` → 没有 → 返回 `aborted: "skipped: codex 未安装"`。
- 有：在 `{scratch}/xmodel/` 建隔离副本（按档位裁剪材料）+ `git init` + README（已知且刻意、已修、settled）→
  `codex exec --skip-git-repo-check --sandbox workspace-write -C <副本> "$(cat prompt.txt)" </dev/null > run.log 2>&1`（`timeout 1200`）→
  runner 把输出转成 finding schema，`lens:"xmodel"`。
- Codex 的发现**走同一条核实流水线**，不直接采信（`prog-a1`：4 条里 2 条被 3/3 驳回）。
- Codex 沙盒看不到截图/图片 → 依赖图片的条目标 `needs_images`，由主会话自己开图（`net-p1`）。
- Codex 给的改写**只采纳问题，不采纳措辞**；allowed 档的补丁由主会话局部重写（`net-p1`：改写过长、删掉 spec 要的论证）。
- 额度：每份作业累计 ≤ 2 次（第 1 轮整体审；`deep` 档可加一次批量裁决）。
- 其他 CLI（如别家厂商的命令行）：规划中。现在 `args.xmodel` 只接受 `true / false`，传对象会直接报错。

## 10. 轮次与终止条件

- **第 1 轮**：全量（按类型默认镜头）。
- **第 2 / 3 轮**：只在**交付物哈希变了**（或换了档位）之后才跑；只审差异：`regression` 必开 + 改动区域相关的镜头（`rounds: first` 的镜头不再自动开）；README 里加「自第 N−1 轮以来的改动」（和上一轮的 `snap/` 比，PDF 用文字层比，同一轮重复 prep 结果不变）+ `settled.json`。

**满足任一就停：**

| # | 条件 | 来源 |
|---|---|---|
| T1 | 本轮核实后 **0 条新 must_fix 且 0 条新 should_fix**（新 = 不在 settled/fixed 里） | 任务约束 |
| T2 | 已跑满 3 轮（由 `/审查` 第 7 步判断，代码不强制） | `db-a2` 回报递减 |
| T3 | 材料（含角色）与上一轮相同、档位也相同、上一轮有报告 → 不重跑，直接给上一轮报告（`prep` 和第 N−1 轮的 `manifest.json` 比，在 `mechanical.json` 写 `same_material_as_prev_round`；`lenses` 和 `run` 再对上第 N−1 轮的 `tier.json`，一样就拒跑，`--force` 越过）| `db-a2` |
| T4 | 本轮 must_fix 全是上一轮改动引入的回归 → 修完只跑**机械回归**，不再起新一轮 agent | `db-a2` R4 |
| T5 | 距截止 < 6 h → 只跑机械检查（由 `/审查` 第 7 步判断）| 推断：重取证会引入新风险 |
| T6 | 他说停 | — |

settled 冻结：`rejected` / `leave` / `fixed` 进 `settled.json`，后续轮**无新证据不得重开**（`prog-a1`、`db-a2`）。
但 `leave` 每条必须带理由，后续轮 README 里连理由一起给 —— 防止清单锚定 reviewer 后集体失明（`db-a2` 教训）。

## 11. 落盘与续跑

```
<课程>/作业/_审查/<代号>/
  审查.json            last_prep_round · spec_feed_allowed（--no-spec-feed 之后一直沿用）· manifest_digest · last_prep_at
  运行记录.md          runId · scriptPath · args · 开跑/结束时间 · 限额事件 · 续跑命令 · 预期产物清单
  材料/                README.txt · MANIFEST.json · 冻结副本 · 文字层 · 页面 PNG
  settled.json         累积：{"rejected": [...], "leave": [...], "fixed": [...]}，每条 {"title", "reason", "round"}（按 title 匹配，不用 F 编号 —— 编号每轮都会变）；格式不对直接报错
  r1/  tier.json · manifest.json · mechanical.json · snap/ · find-<lens>.json · find-xmodel.json · merged.json
       verify-facts-b1.json · verify-marker-b1.json · judge.json
  报告-r1.md / .pdf
  r2/ …
  自查清单.md / .pdf   （forbidden 档才有）
```

- 每个 agent：开工先查自己的输出文件 → 在就读回；做完先 Write 再返回。**文件名由编排层在 prompt 里显式给定**，恢复靠文件名不靠 JSON 内容（`db-a1`：agent 自填的元数据字段二十多种写法）。
- 同会话撞限额：`TaskStop` → `Workflow({scriptPath, args, resumeFromRunId})`。
- 换会话：直接重跑同一 args —— 已落盘的 agent 秒过（不依赖同会话缓存）。
- 判官挂了：`python3 shared/工具/作业审查.py assemble <课程> <代号> --round N` 从盘上 JSON 拼原始报告（零 LLM；档位按 `rN/tier.json`；这一轮还没审过就拒绝；抬头写明没跑成的镜头和剔除计数）。
- 审完：`r*/` 保留（下一轮要读 settled），作业交掉后由 `/总控` 归档压缩。

**args 约定：**

| 字段 | 必填 | 说明 |
|---|:-:|---|
| `root` · `course` · `code` · `round` | ✅ | 项目根（绝对路径）· 课程 · 作业代号 · 第几轮 |

| 防线 | 代码里的位置 |

### 13.2 `run` 流程

```
读 .env（STUDY_PROVIDER / STUDY_API_KEY / STUDY_MODEL / STUDY_BASE_URL）
  + 可选 REVIEW_MODEL（扇出用，默认 STUDY_MODEL —— 规则很长，小模型容易守不住）
  + 可选 REVIEW_JUDGE_MODEL（默认 STUDY_MODEL）
  + REVIEW_CONCURRENCY（默认 4，上限 8）· REVIEW_MAX_CHARS（每次调用的材料上限，默认 120000）
↓
档位闸门：--tier 必须与 --confirm-tier 一致；tier=forbidden → 拒绝并提示用 checklist
打印：「将把以下文件发送给 <provider>/<model>：…；约 k 次模型调用，输入约 T token（粗估 = 字符数 / 3.5 × 调用数）。继续？[y/N]」
↓
Find：镜头库按 type 取默认，去掉 tiers 不含该档的；needs 含 run/db/images 的镜头改为「静态模式」
      ThreadPoolExecutor 并发，每个镜头 1 次调用：system = COMMON + 镜头段 + 档位段，
      user = README + 材料文本（超长截断，截掉的范围写进 not_checked）
      要求只回 JSON（顶层数组、结尾逗号、注释会先修；找不到带 findings 的对象就算失败，绝不当零条）；
      解析失败 → 带错误提示重试 1 次，仍失败记 missing；结果写 r{N}/find-<lens>.json（_fp 相同则跳过）
↓
Merge（本地，无 LLM）：
      · work_quote 归一化空白后必须是作答文本的子串，否则 dropped: quote-not-found（这是它能做的最强机械核实）
      · rule_quote 必须是权威文本子串
      · allowed：old_text 必须在源文件恰好出现一次
      · guided：剥改法字段 + 泄漏正则
      · 同文件 + 行区间相近（±3 行或同一题）+ difflib 标题相似度 > 0.6 → 合并，raised_by++
      · 剔除 settled.json 里的
↓
Verify：facts 镜头批调用（每批 ≤ 8 条；上下文 = README + 权威文件 + 每条前后 8 行的作答片段）→ keep 的再按 8 条一批过 marker
      批次失败或回票不全 → 缺的记 incomplete；回票不全的批次不当缓存
↓
Judge：1 次调用（REVIEW_JUDGE_MODEL）→ judge.json（字段白名单、枚举和数字校验；有发现却一条分级都没给 = 判官失败）
      分级：核实账目是硬约束 —— 没有 facts 票 / facts 成立但没有 marker 票 → 票没收齐；facts 不成立 → 驳回；其余才用判官的分级，判官没给就按 marker 机械推
      报告-r{N}.md 由脚本渲染（格式见 render_report，小节编号和 workflow 版略有不同）
```

默认调用数：5 镜头 + 1–2 facts + 1 marker + 1 judge ≈ **8–9 次**。

### 13.3 必须在报告里明说的局限

报告顶部固定一节「本实现做不到的」：
- **不运行任何代码、SQL、编译或测试**；依赖运行结果的判断全部标 `needs_execution`，列成「请自己跑」清单（附建议命令）。
- **不看图片 / 截图 / 渲染页面**；证据对截图、图表、排版类镜头不跑或只做文字层推理。
- **不能打开文件、不能 grep**：核实只靠「引文是否逐字存在」的本地字符串检查 + 模型推理，强度低于 Claude Code 版的「亲自复现」。
- 材料超过 `REVIEW_MAX_CHARS` 时被截断，截断范围写明。
- 不同厂商模型对 JSON 的遵守程度不同；解析失败两次的镜头记为 missing。
- 学生作答会发送给 `.env` 里配置的第三方服务。

### 13.4 测试

## 14. token 预算估计

经验基数（来自 5 套实测）：每个 sonnet agent ≈ **0.11–0.17 M token**（`net-p1` 108 个 13.2 M；`prog-a1` 31 个 4.3 M；投票 45 个 5.1 M）；agent 自己整份读长 PDF 时可到 1 M+（`rules`）→ 文字层索引 + 工具调用上限把它压回基数。

| 规模 | agent | 估计 token（含 1.3× 重试余量） | 墙钟 |
|---|---|---|---|
| `lite` | 5 | 0.7–1.2 M | 10–20 min |
| `standard` | 9–10 | 1.3–2.6 M | 20–40 min |
| `followup` | 5–8 | 0.8–1.8 M | 15–30 min |
| `deep` | 20–40 | 3–8 M（**按 2–3× 余量报给他**） | 1–2 h（不含等限额重置） |
| Codex 一次 | +1 runner | +0.05 M Claude；Codex 自身额度另计 | +3–13 min（批量裁决 10–30 min，放后台） |
| Python 简化版 | 8–9 次调用 | ≈ 材料字符数 / 3.5 × 调用数，典型 0.2–0.5 M | 2–10 min |

一份作业典型总量：standard 第 1 轮 + followup 第 2 轮 ≈ **2–4 M**。对照：此前单轮 108 agent = 13.2 M、531 次启动约 5.5 h（`net-p1`、`db-a1`）。
估算公式（报给他时用）：`finders + merge + ⌈findings/10⌉ + 1 + judge`，乘 1.3（standard）或 2–3（deep）。

## 16. 明确不做的事

1. **不提交、不上传、不发帖、不发邮件**；报告里的「交前清单」是提醒他做。
2. **不自动推断或放宽档位**；未核不给 `allowed`；放宽只能走交接单 → `/总控` 改分级表。
3. **`forbidden` 档不起任何 agent、不调任何 API、不读他的作答内容。**
4. **`guided` 档不给改好的答案、句子、代码，也不生成盲解**（盘上不留任何完整解答）。
5. **不自动应用补丁**：allowed 档也要他挑、要问「我改 / 你自己改」；guided 档一个字都不改。
6. **不宣布「可以交了 / 定稿」**；只给客观计数。
7. **不重议 AI 政策**，不对政策开调查。
8. **不在没有同意时起 workflow**；不在默认档超过 10 个 agent；不让扇出 agent 继承主模型。
9. **不让 reviewer 改被审文件**，不连生产 / 远程服务器，不访问课程平台。
10. **不给单点预测分数**；不把不同镜头的重叠条目直接相加。
11. **不重开 settled**（除非有新的具体证据）。
12. **不拿同门别的作业或别门课的政策推这一份**。
13. **不动 `shared/` 账本**；需要改的写交接单。
14. **Python 简化版不假装跑过代码 / 看过图**；做不到的写在报告顶部。
15. **Codex 不超过每份作业 2 次**；没装不报错、不提示安装。
16. **不做通用代码质量 / 文风打磨服务**：只报会扣分或会跑错的；polish 级不核实、不排进必改。
